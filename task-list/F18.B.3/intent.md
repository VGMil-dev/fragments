# F18.B.3 — Rúbrica propia y entregas versionadas

## Intención

Completar el modelo de misión para que una actividad tenga criterios propios y pueda organizar varias entregas del mismo proyecto. La configuración debe sobrevivir publicación y recarga como parte de la versión inmutable de la misión, sin cambiar las versiones ya existentes.

## Resultado de este incremento

- El docente configura una rúbrica específica por misión y define entregas ordenadas con tipo, requisitos, fecha opcional y criterios aplicables.
- La publicación congela rúbrica y entregas junto con el snapshot actual de misión, habilidades y contexto Mentor.
- El estudiante consulta esa configuración desde la versión publicada; el sistema no crea otro proyecto ni repositorio por cada entrega.
- Las entregas describen instrucciones y criterios. No implican fechas obligatorias, cálculos de nota, cierres automáticos ni aprobación humana de Mentor.

## Fuera de alcance

Historial/recepción de una entrega por estudiante, asociación de un commit Review a una entrega, progreso automático, rúbrica distinta por entrega, fórmula de calificación, fechas obligatorias, cierre/reapertura, tablas nuevas, migración, proveedor IA o escrituras en producción.
